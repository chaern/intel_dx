# Modbus 통신 정리

Modbus는 PLC, 센서, 계측기와 SCADA·디지털 트윈이 상태값과 설정값을 주고받는 산업용 통신 프로토콜이다. 클라이언트가 기능 코드, 시작 주소, 개수 등을 담아 요청하면, 서버가 값이나 예외 코드를 반환한다. 예를 들어 디지털 트윈의 수집기가 PLC에 압력 레지스터를 주기적으로 읽고, 변환한 값을 화면에 표시한다.

## 1. Modbus RTU와 TCP

| 구분 | Modbus RTU | Modbus TCP |
| --- | --- | --- |
| 전송 경로 | 직렬 통신(현장에서 주로 RS-485) | TCP/IP(기본 포트 `502`) |
| 프레임 구조 | 장치 주소 + 기능 코드와 데이터(PDU) + CRC-16 | MBAP 헤더 + 기능 코드와 데이터(PDU) |
| 연결할 때 확인할 값 | 장치 주소, 전송 속도, 패리티, 정지 비트 | 서버 IP, 포트, Unit ID |

RTU와 TCP는 같은 기능 코드 체계를 사용한다. TCP의 MBAP 헤더에는 요청과 응답을 연결하는 Transaction ID와 대상을 나타내는 Unit ID 등이 들어간다. TCP↔RTU 게이트웨이를 사용할 때는 Unit ID로 하위 직렬 장치를 지정한다. TCP 장비에 직접 연결할 때도 Unit ID는 장비 매뉴얼에서 확인한다.

## 2. 데이터 영역과 기능 코드

| 데이터 영역 | 크기 | 관례적 표기 예 | 읽기 | 쓰기 |
| --- | --- | --- | --- | --- |
| Coil | 1비트 | `00001` | `01` | `05` 단일, `15` 복수 |
| Discrete Input | 1비트 | `10001` | `02` | — |
| Input Register | 16비트 | `30001` | `04` | — |
| Holding Register | 16비트 | `40001` | `03` | `06` 단일, `16` 복수 |

표의 기능 코드는 **10진수**다. 예를 들어 `16`(복수 Holding Register 쓰기)은 패킷에서 `0x10`이다. 각 장비가 지원하는 기능과 쓰기 가능 여부는 매뉴얼에서 확인한다.

**참조 번호와 요청 주소를 구분한다.** 첫 Holding Register를 `40001`로 표기하는 매뉴얼에서 `40001`의 요청 주소는 `0`, `40002`는 `1`이다. `4`로 시작하는 표기는 이 경우 데이터 영역을 구분하기 위한 관례이며, 패킷에는 기능 코드 `03`과 0부터 시작하는 주소가 따로 들어간다. 도구와 장비 매뉴얼은 참조 번호, 1부터 시작하는 번호, 0부터 시작하는 오프셋을 다르게 표시할 수 있다.

## 3. 실습: Modbus TCP로 압력 읽기

아래는 연습용 레지스터 맵이다. 실제 PLC에 연결할 때는 해당 모델의 주소, 자료형, 배율을 적용한다.

| 태그 | 데이터 영역 | 참조 번호 | 요청 오프셋 | 변환 |
| --- | --- | --- | --- | --- |
| 펌프 운전 상태 | Discrete Input | `10001` | `0` | `0` 정지, `1` 운전 |
| 압력 | Holding Register | `40001` | `0` | `uint16` 원시값 × `0.1` bar |
| 탱크 수위 | Input Register | `30001` | `0` | `uint16` 원시값 × `0.1` % |

1. 테스트 서버 또는 시뮬레이터에서 Unit ID `1`, Holding Register 오프셋 `0`의 값을 `253`으로 설정한다.
2. Modbus TCP 클라이언트에서 테스트 서버의 IP와 포트로 연결하고, Unit ID `1`, 기능 코드 `03`, 시작 오프셋 `0`, 개수 `1`을 지정한다. 도구가 참조 번호를 받는다면 해당 UI 규칙에 맞춰 `40001`을 입력한다.
3. 원시값 `253`을 읽고 `253 × 0.1 = 25.3 bar`가 표시되는지 확인한다.

이 요청과 응답을 16진수로 나타내면 다음과 같다. `|`는 MBAP 헤더와 PDU의 경계다.

```text
요청: 00 01 00 00 00 06 01 | 03 00 00 00 01
응답: 00 01 00 00 00 05 01 | 03 02 00 FD
```

두 프레임의 Transaction ID는 `00 01`이다. 요청 PDU의 `00 00`과 `00 01`은 시작 주소와 개수다. 응답 PDU의 `02`는 데이터 길이(2바이트), `00 FD`는 원시값 `253`이다. MBAP의 Length 필드는 Unit ID부터 끝까지의 바이트 수이므로 요청은 `6`, 응답은 `5`다.

## 4. 디지털 트윈에 연결할 때

- **태그 정의:** 장치, Unit ID, 데이터 영역, 오프셋, 자료형, 배율, 단위를 한곳에 기록한다. 32비트 정수나 실수는 레지스터 두 개를 사용하므로, 장비 매뉴얼의 워드 순서와 도구의 바이트 순서 설정을 확인한다.
- **상태 표시:** 값과 함께 마지막 성공 시각과 통신 상태를 저장한다. 읽기에 실패하면 마지막 값을 유지하더라도 화면에 `갱신 지연`이나 `통신 끊김`을 표시해 정상값으로 오인하지 않게 한다.
- **수집 주기:** 같은 장치와 데이터 영역에서 읽을 수 있는 연속 주소는 묶어서 읽고, 화면 갱신 요구와 장치 부하에 맞춰 주기를 정한다.
- **제어 범위:** 모니터링은 읽기부터 시작한다. 쓰기는 테스트 환경에서 검증하고, 운영에서는 권한과 장비 인터록을 거치도록 구성한다. 일반 Modbus TCP는 자체 인증과 암호화를 제공하지 않으므로 장비 포트를 인터넷에 직접 노출하지 않는다.

## 5. 장애 점검

| 증상 | 먼저 확인할 것 |
| --- | --- |
| TCP 연결 실패 | 서버 IP, 포트, 방화벽, 서버의 수신 상태 |
| 연결되지만 응답 없음 | Unit ID, 게이트웨이 설정과 하위 장치 상태. RTU라면 배선과 직렬 설정도 확인 |
| 예외 `0x01` | 장비가 요청한 기능 코드를 지원하는지 확인 |
| 예외 `0x02` | 시작 주소와 개수 전체가 장비의 주소 범위에 들어가는지 확인 |
| 요청은 성공하지만 값이 이상함 | 주소 기준, 자료형의 부호, 배율, 여러 레지스터를 읽을 때의 워드 순서 |
